社群、通知與外部服務的責任邊界

回索引 · 基準 1e2f8cd · 2026-09-14

分享改變資料可見性，也啟動資料庫規則

部分練習與社群共用 gratitude_entries，以 practice_type、is_shared 等區分內容與分享狀態。 前端先做公開內容檢查，資料庫 enforce_content_moderation 再做強制判定；配合自動待審、檢舉與管理員 RPC。 因此 moderation 是保存契約的一部分，不只是頁面上的字詞過濾。 subscriptions.sql 也定義同名社群讀取 policy，部署時要核對各 SQL 的套用順序與最後生效定義。

兩條背景工作需要不同的可靠性

flowchart LR
  W[按讚 / 留言保存] --> T[DB trigger]
  T --> N[pg_net HTTP]
  N --> E[push-notify Edge Function]
  E --> A[APNs]
  L[Python AI 呼叫完成] --> C[asyncio.create_task]
  C --> U[ai_usage_log]

推播 trigger 包住 enqueue 階段例外，避免推播設定錯誤回滾留言。HTTP enqueue 成功不等於送達 APNs 或使用者已讀。 push-notify 驗證 webhook secret、查裝置 token，對失效 token 有處理；本次閱讀範圍未見完整應用層持久重試閉環。 SQL 的 URL／secret 仍是待部署替換的 placeholder，不能據檔案判定線上推播已正確設定。

meter_claude／meter_whisper 用背景 task 寫成本；程序退出可能遺失，_post_ai_usage 也未檢查 HTTP 狀態碼。 usage_metering.py 使用程式內建價目表估算，不是付款帳單；本次沒有查證外部最新價格。 TypeScript Edge 另外有 _shared/metering.ts，未來成本策略要跨執行環境統一。

其他不能漏掉的執行位置

  • /api/transcribe 驗證登入、限制類型與 10 MB，配置 20/minute IP 限流；async handler 內直接呼叫同步 OpenAI client，可能阻塞 event loop。建議換非同步 adapter 或有界執行緒，並統一逾時策略。
  • 其他 AI POST 未見同樣的 limiter decorator。不要從語音有限流推論全站已有 AI 成本保護。
  • Edge 的 delete-account 先驗證登入，再以 admin client 刪除該 Auth 使用者。要遷移時需盤點 FK cascade、裝置與相關資料清理，不可只刪 profiles 便宣稱流程等價。
  • Python 與 Edge 都有名為 gratitude-summary 的實作；已讀取的前端 fetchGratitudeSummary 指向 Python。不能僅看同名函式就認定 Edge 版本仍有流量。
  • /healthz 回套件版本與 commit，是存活／版本資訊，沒有查 DB 或 AI 可用性，不能當完整就緒檢查。

提案與驗收

把 notification、AI provider、cost recorder 定義為介面，業務用例決定失敗語意。 需要可靠投遞者採持久工作與有限重試；可容許遺失者明確標示並監測遺失率。 不要讓一般通知與安全警示共用「失敗忽略」預設。 補上外部 HTTP 狀態檢查、request／job 關聯 ID、模型用量與各 use case 失敗率。

驗收：推播掛掉仍可保存留言；公開內容審查無法被直接 DB 呼叫繞過；語音慢請求不拖住其他請求； 成本記錄故障可觀測；若要求可靠投遞，程序重啟後仍找得到未完成工作。
