02 / EPHEMERAL

快取與本機資料

記憶體、localStorage、sessionStorage、Cache API、API provider prompt cache 的資料形狀、生命週期與失效方式。

device-local TTL 不可作安全判斷

對 V2 最有用的現況觀察

  • 一張 gratitude_entries 承擔多種業務。 它既是感恩日記，又被拿作過程目標、工作坊的社群貼文；欄位與 payload jsonb 共同表達不同型態。
  • 模組內容與回答高度 JSONB 化。 pro_modules、pro_entries、pro_reviews、pro_assessment_results 把版本與結構的責任留在 application code，DB 幾乎無法驗證內容形狀。
  • 規則散落且 SQL 採人工套用。 RLS / trigger / RPC 與 FastAPI 共同控制流程，沒有單一 migration pipeline，因此「檔案 schema」不等於「線上 schema」。
  • 本機資料不是資料庫快取層。 草稿與 UI flag 沒有統一 key namespace、版本、帳號切換或清除策略；它們可改善體驗，但不可用來決定權限或業務真相。
