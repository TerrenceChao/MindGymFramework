核心身分、測驗與日常練習

根節點是 Supabase managed auth.users；所有應用層使用者資料經 profiles.id 連結。大多數個人資料由 client 以登入 JWT 直連 PostgREST，RLS 的 user_id／id 條件是主要隔離。

profiles應用使用者主檔 · 1:1 auth.users · RLS：已登入可讀、本人建立／更新

PK/FK id → auth.users.id；直接 client CRUD

  • iduuidPK；auth 使用者
  • name, avatartext?名稱、頭像代碼
  • current_streakintegerdefault 0；連續紀錄
  • perma_[p|e|r|m|a]_xpintegerdefault 0；五向度 XP，另有原子 RPC
  • founding_invite_shown_attimestamptz?創始邀請已顯示
  • terms_accepted_at/versiontime / text?條款同意稽核
  • created_attimestamptzdefault now()
perma_scoresPERMA 測驗結果歷程 · 個人可讀；同意時專業夥伴可讀

PK id；FK user_id → profiles；後端寫入報告

  • id, user_iduuidPK；使用者關聯
  • p/e/r/m/a_scoreint?CHECK 1–5
  • report_jsonjsonb?JSONB AI 測驗報告，shape 由 backend 決定
  • created_attimestamptz歷程時間
gratitude_entries感恩日記 + 多種社群貼文的共用表 · 現況核心多型資料表

FK user_id → profiles；直接 client CRUD；公開讀取另受 community RLS 與 moderation status 影響。

  • id, user_id, entry_dateuuid / datePK；作者；default CURRENT_DATE
  • item_1..3text?原始感恩三件事；舊貼文主內容
  • tag_1..3, target_1..3text?AI/使用者標籤與感謝對象
  • ai_feedbacktext?AI 回饋
  • is_shared, anon_namebool / text?社群可見與匿名名稱
  • avatar, use_real_nametext? / bool?社群顯示設定
  • practice_typetextdefault gratitude；亦用於 process_goal、workshop_*
  • payloadjsonb?JSONB 多型附載：moment {v,event,who,when,where,insight}；boost {v,situation,suggestion}；workshop_id 亦置於此
  • moderation_statustextdefault ok；ok / hidden / removed
  • moderated_at/notetime / text?審查稽核
  • created_attimestamptz排序與社群／額度衍生使用

Index practice_type；payload→workshop_id expression。注意：同表同時作私人日記、社群貼文與多練習容器。

  • created_at, updated_attimestamptz時間

FK user_id；索引 (user_id, log_date DESC)、(user_id, log_kind)

  • had_focus_momentbooleandefault false
  • focus_description/conditions/feelingstext / text[]專注事件與條件／感受
  • moment_who/when/wheretext?moment 補充資料

  • ai_feedback, created_attext? / timeAI 回饋、建立時間
morning_logs早晨啟動紀錄 · 多筆

daily_schedule日程練習排程 · 完成狀態不落表，改由其他練習資料推導

社群、通知與內容安全

likes貼文讚 · 含機器人按讚旗標；插入 trigger 會送推播

UNIQUE (entry_id, user_id)；但 user_id 可為 NULL，bot like 以 is_bot=true 寫入。

  • iduuidPK
  • entry_id, user_iduuid?FK → gratitude_entries / profiles
  • is_botbooleandefault false；bot 不觸發 push
  • created_attimestamptz時間
comments貼文留言與巢狀回覆 · 插入 trigger 送推播／審查

登入者可讀正常留言；作者可讀自己的 hidden/removed 資料。

  • id, entry_id, user_iduuidPK；FK → post / author
  • parent_iduuid?self FK → comments.id；巢狀回覆
  • anon_name, contenttext? / text顯示名／必填內文
  • moderation_statustextdefault ok；ok / hidden / removed
  • moderated_at/note, created_attime / text?審查、建立時間
comment_likes留言按讚 · 防重複關聯表

UNIQUE (comment_id, user_id)；登入者可讀、本人建立／刪除。

  • iduuidPK
  • comment_id, user_iduuidFK → comments / profiles
  • created_attimestamptz時間
bot_like_queue機器人按讚延遲工作佇列 · pg_cron 每 2 分鐘處理

RPC / scheduled job 由 schedule_bot_likes() 建 5–10 列，process_bot_likes() 消費。

  • id, entry_iduuidPK；FK → gratitude_entries
  • scheduled_attimestamptz到期時間
  • processed_attimestamptz?消費紀錄
  • created_attimestamptz建立時間
reports內容檢舉與處理佇列 · entry/comment 多型目標

直接 client insert；admin 透過 RPC 處理。partial UNIQUE indices 防重複檢舉。

  • id, reporter_iduuidPK；檢舉者 FK
  • target_typetextCHECK entry / comment
  • entry_id, comment_iduuid?兩者其一的 FK 目標
  • reported_user_iduuid?FK；刪使用者時 SET NULL
  • reasonstext[]default {}
  • notetext?檢舉說明
  • status, sourcetextdefault pending / user；後續 ALTER 加入
  • resolution, admin_notetext?處理結果
  • reviewed_by/at, created_atuuid? / time審查稽核
blocks封鎖關係 · 前端自行載入並過濾動態牆

UNIQUE (blocker_id, blocked_id)；沒有 DB policy 去改變其他查詢。

  • iduuidPK
  • blocker_id, blocked_iduuidFK → profiles
  • blocked_labeltext?封鎖當刻顯示名稱，避免查真名
  • created_attimestamptz時間
moderation_rules資料庫內容審核規則字典 · 一般使用者不可讀

admin only 寫入會由 trigger 的 moderation_verdict() 判定。

  • id, patternuuid / textPK；pattern UNIQUE
  • categorytextCHECK hate/harassment/sexual/violence/spam/self_harm_promotion
  • actiontextCHECK block / hide / flag
  • normalized, enabledbooleandefault true
  • created_attimestamptz時間
user_suspensions停權狀態 · 每人一列

PK/FK user_id；寫入走 admin RPC；is_suspended() 供 trigger 使用。

  • user_iduuidPK／FK
  • reasontext?停權原因
  • untiltimestamptz?NULL 表示未設到期

專業夥伴、個案模組與危機流程

這個子域的安全性依賴 roles、enrollment、RLS 與大量 SECURITY DEFINER RPC。資料的機密性不只取決於 table 欄位，還取決於讀取是否必須經過 RPC 投影。

user_roles角色安全根 · 不放在 profiles，避免使用者自行改 profile 提權

PK (user_id, role)；role CHECK practitioner / admin；第一位 admin 需手動 SQL。

  • user_id, roleuuid / text複合 PK；使用者與角色
  • granted_byuuid?FK → profiles
  • created_attimestamptz授予時間
practitioner_applications專業夥伴申請 · 每使用者一份

user_id UNIQUE；approved/rejected 走 admin RPC；核准時新增 user_roles。

  • id, user_iduuidPK；FK；user_id UNIQUE
  • name, title, organizationtext申請人資訊
  • license_info, motivationtext?資格與動機
  • statustextpending / approved / rejected
  • admin_note, created_at, reviewed_attext? / time審核資料
pro_modules專業模組本體 · draft/published 雙槽 + 多型 kind

JSONB 個案只應從 get_my_modules() 取得 published projection；直接 UPDATE policy 刻意不存在，改走 RPC。

  • id, owner_iduuidPK；FK → practitioner profile
  • title, description, est_minutestext / int?模組 metadata
  • kindtextdefault practice；CHECK practice / diary / assessment
  • draft_contentjsonb?編輯／送審內容
  • published_contentjsonb?核准後給個案的內容
  • statustextdraft/pending_review/approved/rejected/archived
  • ai_reviewjsonb?最近 AI 審核標籤
  • admin_notetext?退件／下架原因
  • submitted/published/created/updated_attimestamptz?生命週期時間
pro_module_review_log模組審核軌跡 · append-only 設計意圖

INSERT 僅 RPC / service key；owner/admin 依 policy 讀。

  • id, module_iduuidPK；FK → pro_modules
  • actiontextsubmitted / approved / rejected / takedown
  • actor_id, noteuuid? / text?操作者、說明
  • content_snapshot, ai_reviewjsonb?JSONB 當下內容與 AI 審查快照
  • created_attimestamptz時間
invite_codes模組邀請碼 · 個案不可直接 SELECT，避免枚舉

RPC regenerate_invite_code 作廢舊碼並建新碼；preview/redeem 是受控入口。

  • id, module_iduuidPK；FK
  • codetextUNIQUE；8 字元秘密
  • is_activebooleandefault true
  • created_at, revoked_attimestamptz生命週期
pro_enrollments個案同意與追蹤關係 · 模組 × 使用者唯一

UNIQUE (module_id, user_id)；re-redeem 時 upsert 重開 active；停止後專業夥伴看不到歷史資料。

  • id, module_id, user_iduuidPK；FK → module / 個案
  • practitioner_iduuidFK；兌換當下 owner snapshot
  • statustextactive / stopped
  • share_permabooleandefault false；授權讀 PERMA
  • consented_at, stopped_at, created_attimestamptz同意生命週期
pro_entries個案在專業模組的作答歷程

僅 active enrollment 的本人能 INSERT；個案／其專業夥伴依 RLS 讀。

  • id, module_id, user_iduuidPK；FK
  • answersjsonbJSONB 原始設計：{ block_id: answer }；實際 shape 隨 kind/content 演進
  • ai_feedbackjsonb?v2 ALTER；後端 service key 寫的每日 AI 回饋
  • entry_date, created_atdate / time日期與建立時間
pro_reviews專業日記／內建感恩的 AI 回顧快取與通知來源

backend service key INSERT；UNIQUE (user_id,module_id,review_type,period_start) 防同週重生。週摘要額外 ALTER 將 type 納入 weekly_digest。

  • id, user_id, module_iduuidPK；FK；module_id NULL=內建感恩
  • review_typetextoverall / weekly / gratitude_weekly / weekly_digest
  • period_start, period_end, entry_countdate / int回顧範圍
  • contentjsonbJSONB 報告；不同 type/v 有不同 shape
  • created_at, read_attimestamptz通知／已讀
pro_assessment_results質性測驗結果 · practitioner/client 兩份報告

個案不直接讀 table，需 RPC 遮蔽 practitioner_report；release 前 client_report 回 NULL。

  • id, module_id, user_iduuidPK；FK
  • answersjsonbJSONB { question_id: string }
  • practitioner_reportjsonb?僅專業夥伴／後端
  • client_reportjsonb?發佈後個案可見
  • statustextpending_release / released
  • created_at, released_attimestamptz生命週期
crisis_alerts危機警示 · AI / keyword 來源、可由專業夥伴 ack

後端服務 key 是主寫入；個案 client 的 keyword fallback 可 INSERT（須 active enrollment）。

  • id, user_id, practitioner_iduuidPK；FK → 個案 / 專業夥伴
  • module_id, entry_iduuid?FK → module / pro entry
  • sourcetextkeyword / ai
  • severitytextmedium / high；default high
  • matched_termstext[]default {}
  • acknowledged_at, created_attimestamptz處理與建立時間

方案、權益與平台設定

subscriptions每位使用者的方案資料 · 目前多為標籤，不是有效權益真相

RPC 只有 admin set_user_subscription() 可寫。現有 is_pro(uid) 對任何登入者為 true，因此此表目前不限制功能。

  • user_iduuidPK／FK → profiles
  • tier, statustextfree/pro/pass；trialing/active/grace/canceled/expired
  • is_founding_memberboolean徽章標籤
  • price_plan_codetext?鎖價用方案碼；無 FK
  • started_at, expires_attimestamptz?時間；NULL 可表示無期限
  • granted_by, note, updated_atuuid? / text? / time管理稽核
pricing_config公開可讀的遠端價格表

plan_code PK；未見外鍵連到 subscriptions。

  • plan_codetextPK；如 pro_monthly / pro_yearly
  • periodtextmonth / year
  • amount_centsinteger標準價格（分）
  • founding_amount_centsinteger?創始價
  • currency, is_active, sort_ordertext / bool / intTWD、啟用、排序
  • updated_attimestamptz時間
paywall_config單列設定（id=1）· 公開可讀

RPC admin 更新；原始 schema 後續 ALTER 加入 free_view_limit。

  • idintegerPK，CHECK id=1
  • founding_quota_total/enabledint / bool名額設定
  • varianttextA / B
  • free_view_limitintegerdefault 15；目前 is_pro 開放時不生效
  • updated_attimestamptz時間
paywall_intents付費 CTA 意願量測 · 不是金流交易

使用者可寫自己的 intent；不可讀自己的資料；admin 可讀。現況不改變 entitlement。

  • id, user_iduuidPK；FK
  • plan_code, variant, sourcetext來源如 onboarding/settings/soft_paywall
  • created_attimestamptz時間
app_config原生殼強制更新設定 · ios / android 一平台一列

公開可讀；admin RPC update_app_config() 寫入；依賴 is_admin()。

  • platformtextPK；ios / android
  • min_versiontext最低 shell 版本
  • update_url/messagetext?商店 URL、訊息

營運、成本與可觀測性

usage_snapshots外部服務用量每日快照 · service role only

RLS 無 policy；UNIQUE (captured_at, source, metric)。資料寫入端是監測腳本。

  • idbigintidentity PK
  • captured_at, source, metrictime / text時間、來源、指標
  • value, unit, limit_value, pctdouble?通用數值與上限
  • cost_usddouble?AI 等來源的成本
  • rawjsonb?JSONB 原始 API 回應片段
ai_usage_log每次 Claude / Whisper 估算用量記帳 · service role only

backend service key FastAPI fire-and-forget 寫入，不阻擋主流程。

  • id, created_atbigint / timeidentity PK、時間
  • provider, source, modeltext供應商、功能、模型
  • user_iduuid?觸發者；沒有 DB FK
  • input/output_tokensinteger?基本 token
  • cache_write/read_tokensinteger?Claude prompt cache 計價指標；不是本系統 Redis
  • audio_seconds, cost_usdnumeric?Whisper 時數、估算成本
重要 DB functions / triggers（不是 tables，但改資料流）
  • increment_perma_xp()：profile 五維 XP 原子增加。
  • get_my_entitlements()、community_unlocked()：權益投影；目前所有登入者 is_pro=true。
  • get_community_preview()：RLS 外的限量社群預覽。
  • preview/redeem_invite_code()、get_my_modules()：專業模組的安全資料投影。
  • get_my_assessment_results()：隱藏尚未發布的個案報告。
  • schedule_bot_likes()、process_bot_likes()：佇列 → likes。
  • enforce_content_moderation()、autoflag_content()、autohide_reported_content()：對 posts/comments 的 trigger。
  • notify_push_on_interaction()：likes/comments/subscriptions trigger → pg_net → Edge/APNs。
  • ai_usage_summary()、get_db_size_bytes()：service-role 營運查詢。
